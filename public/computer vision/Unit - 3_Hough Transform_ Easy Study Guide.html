Session 1

1. The Big Idea: Voting for Lines

A Hough Transform (HT) finds simple shapes (mostly straight lines) in an image, even if the picture is noisy or the line is broken. It was invented by Paul Hough (1962) and improved by Duda and Hart (1972).

Simple story: Imagine 10 friends standing in a row, and some strangers scattered around. Every person draws all possible lines through themselves. The one line that everyone in the row drew is the real line. Strangers draw lines nobody else shares, so those lines get ignored. That is "voting".

Point to line duality

A point can be described by its coordinates or by the set of all lines passing through it. If points are on one line, exactly one line is common to all their sets. That "multiple hit" reveals the line. This is why HT ignores noise points and even unwanted shapes like circles.

Image space: a point is a point. Parameter (Hough) space: a point becomes a curve, and a line becomes a single point.

Pros and cons of HT

Good: works with noise, gaps, partly hidden lines; detects many lines at once; needs no prior knowledge of position.
Bad: slow on big images; uses lots of memory; needs careful tuning of bin size and threshold; sensitive to quantisation errors; hard to extend to complex shapes.
Session 1

2. The Maths: Two Ways to Write a Line

Way 1: slope-intercept

y = m·x + c

m = slope, c = where it crosses the y-axis. For a fixed point (x₀, y₀): c = −x₀·m + y₀, which is itself a line in (m, c) space. Two points on the same line give two lines that cross at (m*, c*).

Problem: a vertical line (x = 5) has infinite slope, so the parameter space is unbounded and cannot be stored in a grid.

Way 2: normal (polar) form, by Duda and Hart

ρ = x·cos θ + y·sin θ
  • ρ (rho): shortest (perpendicular) distance from origin to the line.
  • θ (theta): angle of that perpendicular, measured from the x-axis.

Bounds: ρ goes from −D to +D (D = image diagonal); θ from 0° to 180° (or −90° to +90°). Everything is finite, so it fits in a grid.

3. The Algorithm Step by Step

  1. Edge detection. Use Canny or Sobel to make a binary image (edge pixel = 1, rest = 0).
  2. Parameterise. Use ρ = x cosθ + y sinθ.
  3. Accumulator array. A 2D table (grid): one axis is ρ bins, the other is θ bins. Each cell counts the edge pixels supporting that line. It is also called Hough space or voting array.
  4. Voting. For every edge pixel, for every θ (0° to 180°), compute ρ and add 1 to that cell.
  5. Find peaks. Cells with high counts are real lines (use a threshold or local maxima).
  6. Map back. Turn each peak (ρ, θ) into a line drawn on the image.
Pixel (2,3) at θ = 45°: ρ = 2·0.707 + 3·0.707 = 3.54. Do this for all θ and you get one curve. Do it for every edge pixel and look for where curves pile up.

Worked problem (10×10 matrix with a diagonal)

The 1s form a diagonal staircase, so all its pixels lie on one line. Every one of them votes for the same (ρ, θ) cell, which becomes the clear winner.

Exam tip: your notes say the peak is at θ=45° with 3 votes. That is only a simplified demo. For a line going up-right at 45° the normal actually points at 135° (or −45°), and with 8 edge pixels the peak would get 8 votes. Check with your teacher which version they want.

Variants

Standard HT: all pixels vote for all angles. Robust but slow.
Probabilistic HT: votes using random samples of edge points. Faster, good for real time.
Generalized HT: detects any shape using a template (see section 10).

Accuracy vs resolution (discretisation)

Bins are like boxes of a fixed size: finer boxes = more accurate but more memory and time; coarser = faster but less precise.

Session 2

4. Foot-of-Normal Method and Line Localisation

The foot of the normal is the point (x₀, y₀) where a perpendicular dropped from the origin touches the line. It uses the same equation ρ = x cosθ + y sinθ and has the same benefit: it handles vertical and horizontal lines with finite numbers.

The clever part: each edge pixel also has a gradient (gx, gy) which points across the edge, i.e. along the normal. So the angle θ is already known from the gradient, and the pixel casts one vote (its foot of normal) instead of a whole curve. This is faster and gives a sharper peak. With a slightly wobbly line, the votes make a small cluster near the true foot.

Longitudinal line localisation

Finding long, straight, prominent lines (such as lane markings). Steps: edge detection (Canny), Hough voting, strong peaks mean long lines, extract peaks, then post-process by filtering orientation (near vertical/horizontal), length or position.

Uses: lane detection in self-driving cars, finding anatomy in X-rays/CT, spotting pipes and rails in factories.

5. Noise and Discretisation: What Hurts Accuracy

Noise typeWhat it isEffect
Random (salt-and-pepper)Stray edge pixelsRaises background votes, lowers signal-to-noise ratio (SNR); weak lines missed, false lines found
StructuredPatterns like compression or ringingGhost peaks that look like real lines
Edge localisation errorEdge is found a little off (ε)ρ error = εx·cosθ + εy·sinθ; peak gets wider and shifted
Missing points (gaps)Occlusion, weak contrastLower peak; may fall below threshold (false negative)

Threshold dilemma: false detection if noise votes ≥ T; missed line if true votes < T. No single T is perfect for all images.

Discretisation

  • ρ bin width: Δρ = 2D / N_ρ, rounding error ≤ Δρ/2. D = √(W²+H²).
  • θ bin width: Δθ = 180° / N_θ. Since dρ/dθ = −x sinθ + y cosθ, points far from the origin shift a lot for a small θ step, so accuracy depends on direction.
  • Peak splitting: bins too coarse, so one line's votes spread over several cells (many candidates for one line).
  • Peak merging: bins too fine/close, so two nearby lines look like one.
512×512 image: D ≈ 724 px. Standard choice: 1° steps (N_θ=180) and Δρ = 1 pixel, giving an accumulator of about 2D × 180 cells. Very coarse (72×90 bins, Δρ≈20 px) gives poor results; very fine (2896×1440) is slow with diminishing returns.
Session 3

6. Line Fitting: Least Squares and RANSAC

Final line fitting

HT gives infinite lines (ρ, θ). To get real segments: collect edge pixels that voted for the peak, take min and max coordinates as endpoints, optionally refine with least squares, then draw.

Least squares finds the line that minimises the sum of squared distances to all points. Limitation: it is sensitive to outliers. One far-away point drags the whole line towards it.

RANSAC (Random Sample Consensus)

Fit a model to data with many outliers. Inliers = points that agree with the model, outliers = points that don't.

  1. Pick 2 random points (minimum for a line).
  2. Make the line y = ax + b.
  3. For all points compute distance d = |ax − y + b| / √(a²+1).
  4. Inlier if d < threshold t. Count inliers (the "support").
  5. Keep the model with the most inliers. Repeat N times.
  6. Optionally refit using all inliers with least squares.
Problem 1: pick (2,4),(6,12), so slope = 8/4 = 2, b = 0, line y = 2x. Points on it have d = 0. (5,25) gives |10−25|/√5 ≈ 6.7 and (7,3) gives |14−3|/√5 ≈ 4.9, both outliers. 10 inliers, best line y = 2x.
Problem 2 (t = 1.5, need d = 5 inliers, N = 10 trials; true line y = 2x+1): Trial 1 picks P2(2,5) and P8(2,10), a vertical line x=2, only 2 points close, rejected. Trial 2 picks P1(1,3.1), P5(5,11): slope 1.975, intercept 1.125, so y = 1.975x + 1.125. Distances: P1–P7 are all under 0.5 (inliers), P8 = 2.20, P9 = 4.06, P10 = 6.07 (outliers). Support = 7 ≥ 5, so accepted as best.
A bad sample (containing an outlier) simply gives low support and is thrown away. That is why RANSAC survives outliers.
Session 4

7. Circle Detection (Circular Hough Transform)

(x − a)² + (y − b)² = r²

A circle needs 3 parameters (centre a, b and radius r), so the Hough space is 3D.

  1. Detect edges (Canny).
  2. For each edge pixel (x,y) and each radius r in range, possible centres are a = x − r cosθ, b = y − r sinθ for θ = 0° to 360°. Vote at (a,b,r).
  3. Peaks give centre and radius.

Why centre location is inaccurate

  • Natural edge width adds error.
  • Noise moves the edge position and the estimated edge direction.
  • Object itself may be distorted (need a robust average).
  • Poor illumination makes it look distorted.
  • The edge orientation operator has its own inaccuracy.

Fixes: subpixel refinement (OpenCV HoughCircles returns whole numbers), finer bins (costs time), two-stage or phase-coding methods (still struggle with concentric or hidden circles).

Speeding it up

  • Sampling: scan only every n-th line (factor α).
  • Simpler edge detector: two-pixel differencing instead of Sobel (fewer multiplications and square roots).
  • Chord bisection: on each scan line find where the object starts and ends, take the midpoint, and vote in a 1D space (x for horizontal scans, y for vertical). Peaks give the centre. It needs at least 3/4 of the circumference present.

Original time T₀ = N²s + S·t₀. Chord method T = 2(N²q + Q·t). Gain G = (N²s + S·t₀) / (2α(N²q + Q·t)). About 3× from sampling and 3× from simpler edges gives up to ~25× faster (α down to 0.1). If a fraction β of data is lost, γ = 1 − β is left and accuracy drops to √γ of the best. Edge threshold matters: too low gives false edges, too high loses sensitivity.

Fast centre-finding: (1) horizontal scans, midpoints in x-space; (2) vertical scans, y-space; (3) find peaks; (4) test the candidate centres.

8. Ellipse Detection

An ellipse needs 5 parameters: centre (xc, yc), major axis a, minor axis b, orientation θ. A direct HT would need a 5D space, which is huge, so clever shortcuts are used.

Diameter bisection (Tsuji and Matsumoto, 1978)

Find pairs of edge points whose edge directions are opposite (antiparallel). They could be ends of a diameter, so their midpoint is a candidate centre. Vote for midpoints; peaks are centres.

Good: simple. Bad: m points give m(m−1)/2 pairs (slow); also finds rectangles, circles and other symmetric shapes; sensitive to clutter; needs much of the boundary visible.

Verification: for a true ellipse, 1/OP² + 1/OQ² = 1/R² (OP, OQ perpendicular semidiameters, R constant). Make a histogram of R; a clear peak confirms an ellipse.

Chord-tangent (Yuen et al., 1988)

For two edge points P1, P2: draw tangents meeting at T; M is the chord midpoint. The centre lies on line TM, beyond M (segment MK). Vote only along that segment. Better with occlusion and perspective; slower as it votes along lines.

Parameter estimation

Ax² + 2Hxy + By² + 2Gx + 2Fy + C = 0, with AB > H²

After finding the centre, get orientation and axes by least squares or a smaller second-stage Hough transform.

Session 5

9. Real Uses: Iris Location and Hole Detection

Iris location

Why: face analysis, gaze direction, biometric ID. First find the face to set a region of interest (ROI). The iris is a round, high-contrast shape. Challenges: light iris colour or low contrast, eyelid/eyelash occlusion, ellipse shape from gaze angle. Use Canny edges plus Circular HT. Gradient-weighted HT gives stronger votes to strong edges, so peaks are sharper and eyelid or skin-fold edges matter less. The ellipse's eccentricity helps estimate gaze. Typical radius is ~17.5 px; accurate gaze or biometrics needs ~100 px.

Hole detection

Same circle methods, but holes are darker than the background (negative contrast), so votes go a distance 2R along the edge normal. Large holes are easy. Small holes suffer from poor light and weak contrast. Very small holes (1 to 2 pixels) use template matching with a Laplacian mask that sums to zero (so brightness changes don't matter):

−1 −1 −1 / −1 8 −1 / −1 −1 −1

Then threshold the result. Bigger holes need impractically big masks, so use HT. Circular holes are isotropic (the same in all directions) and less biased than corners, ideal for precise object location.

Sessions 6 and 7

10. Generalized Hough Transform (GHT)

For shapes with no simple equation (a key, a leaf, a bolt). You teach it the shape through a template.

  • Pick a reference point L (often the centroid; for an ellipse, its centre).
  • For each boundary point (x,y) store the displacement r = (x₀ − x, y₀ − y) and the edge direction θ.

R-table

A lookup table indexed by edge orientation θ: R(θ) = {(rx, ry), …}. For concave shapes one θ can have several vectors (multivalued).

Teach GHT a triangle logo. Later, an edge pixel pointing "up-right" looks up its row and votes at the spots where the triangle's centre would be. If the logo is truly there, hundreds of pixels vote for the same centre.

Design choices

  • Reference point: must be stable; centroid is common.
  • Orientation quantisation: bins of angle. Fine = precise but heavier; coarse = light but ambiguous.
  • Translation invariance: built in (vectors are relative to L).
  • Rotation and scale: not built in. Rotate or scale the vectors during voting, or store several R-tables. This adds dimensions: (x,y), then (x,y,φ), then (x,y,s,φ).
  • Ellipse template: uses the prototype's boundary to centre vectors, so only a 2D centre search is needed instead of 5D.
  • Cost: building ≈ N boundary points; voting ≈ O(M·k) for M edge pixels and k vectors per bin; rotation and scale multiply it.

Good: robust to occlusion and noise, finds many instances, works for any contour. Bad: big parameter space and memory; fake edges give false peaks; needs hierarchical or projection tricks.

Spatial matched filtering (template matching)

Slide a template over the image and compute correlation at each spot; peaks mean the object is likely there. This is optimal for known shapes in white noise. Problems: changing illumination, non-white noise, high cost. Fixes: zero-mean templates (subtract the mean), smaller zero-mean subtemplates, thresholding, noise-whitening high-pass filter.

11. Pose Estimation Accuracy (Affine)

Pose = where the object is and how it is turned: translation, rotation, scale, and (for affine) shear. An affine transform keeps straight lines and parallelism but not angles or lengths:

[x′ y′]ᵀ = A·[x y]ᵀ + t

A holds rotation, scale and shear; t = (tx, ty) is the shift. Accuracy means comparing estimated values (with hats) to ground truth.

12. Probabilistic Voting and Feature Collation

Plain voting counts every vote as +1. Probabilistic voting gives each vote a confidence weight wᵢ in [0,1]: A(x,y) = A(x,y) + wᵢ. Weights come from gradient magnitude, edge strength, orientation consistency, feature match confidence, and distance from the expected contour. Strong evidence counts more; weak evidence counts less.

Bayesian view

H = "object centre is at (x,y)", Eᵢ = evidence from feature i. If features are independent: P(H|E) ∝ ΠP(Eᵢ|H). Taking logs turns the product into a sum, log P(H|E) = Σ log P(Eᵢ|H), so accumulator values act as log-likelihood scores.

More ideas

  • Occlusion: hidden parts give no votes, but strong visible features still make a peak; noisy edges are down-weighted.
  • Feature collation: combine edges, corners, texture, intensity gradients and shape-context features, each weighted by reliability, into one evidence score.
  • Normalisation: divide by number of features, by expected visible contour length, or by object size, so big objects don't win unfairly.
  • Evaluation: detection probability, false-positive rate, precision/recall, ROC curves, localisation error.
  • Gains: robustness to noise, stability with partial evidence, reliability in clutter. Cost: extra weight calculations.
Session 8

13. GHT Scalability Problems

  • Dimension growth: 2D (translation), 3D (+rotation), 4D (+scale), 5D+ (affine). With k bins per parameter the accumulator holds k^d cells (exponential).
  • Memory: R-tables (more for several scales/rotations) plus the huge accumulator, a problem on embedded devices.
  • Computation: O(M·k), multiplied by the extra bins.
  • Discretisation: fine bins are accurate but big; coarse bins are small but imprecise.
  • Multiple objects: votes overlap and peaks merge.
  • High resolution: more edge pixels and bigger voting area.
  • Real time: memory, voting, multi-dimensional peak search; needs GPU or approximations.
  • Clutter: spurious edges blur peaks and cost more filtering.
If each of 4 parameters has 100 bins: 100⁴ = 100,000,000 cells. Add a 5th and it is 10 billion.
Session 9

14. HT and GHT in Modern Vision, and Upgrading Them

Today's role: deep learning leads, but HT/GHT stay useful as a geometric check: confirming lane boundaries, document text lines, circular parts, medical structures and fixed-shape components. They are interpretable (explicit geometry) and need no big labelled dataset. But deep models are better for textures, non-rigid objects and variation, and scale better, so HT/GHT are rarely the main detector. Hybrid idea: a neural network predicts edge maps or regions, then Hough voting enforces geometry.

Modernisation strategies

Parallelise: pixels vote independently, so use GPU/CUDA/multi-core.
Adaptive bins: coarse-to-fine search, refine around peaks.
Weighted voting: confidence-based votes.
Hybrid with ML: network gives feature maps; HT verifies geometry.
Save memory: sparse accumulators; randomised or probabilistic HT.
Handle transforms: normalise or align images instead of adding dimensions.
Edge pruning: drop weak edges, gradient thresholds, ROI filtering.
Embedded speed: fixed-point maths, hardware acceleration, FPGA.
Modular design: HT as a plug-in inside a bigger pipeline.
